EPISODE #138 ・ [B16] 💻 パターンB：校務DX・ICT・ネットワーク

見えない壁の正体を暴く――「繋がらない」の迷宮を解き明かす診断の光

🏷️ カテゴリ・領域：校内ネットワーク・DNS/プロキシ診断（OSI参照モデルに基づく障害切り分け / DNS名前解決とキャッシュ確認 / 教育委員会プロキシ・フィルタリング設定 / 同時接続セッション数の制御）
👥 登場人物：年配教諭・大塚先生（教職27年目・視聴覚主任） × 若手教諭・日向先生（教職4年目・情報科）
💡 解決フレームワーク：ネットワーク層ごとの切り分け診断（Ping / DNS名前解決 / Webフィルタリング・プロキシのホワイトリスト制御 / CDNキャッシュ）

窓の外では、初夏の陽光が中学校の校庭を白く照らしていた。しかし、３年Ｂ組の教室の空気は、それとは対照的に険悪なものに包まれていた。

「……先生、また『ページが表示できません』って出ちゃいます」
　生徒の一人が、手元のタブレットを見つめながら困惑した声を上げた。
　総合学習の時間。生徒たちは、地元の特産品を活かしたビジネスプランを立案するため、特定の調査用Webサイトにアクセスしようとしていた。しかし、画面に表示されるのは無慈悲なエラーメッセージだけだ。

「ええっ、また！？ さっきまでは見られたじゃないの」
　別の生徒が声を荒らげる。教壇では、視聴覚主任を務める大塚先生が眉間に深い皺を刻んでいた。彼は長年、学校の行事や映像制作を支えてきたベテランだ。しかし、近年の急激なデジタル化、特に「GIGAスクール構想」による一斉導入以降、ネットワークの挙動については常に「不可解な壁」を感じていた。

「えーっと、みんな落ち着いて。今、先生が確認するから……」
　大塚先生は、慌てて教卓の横にあるLANポートの配線を点検し始めた。彼は必死の形相でケーブルを抜き差ししている。
「よし、もう一度挿すぞ……あ、これだ。あ、でも全然違う。他のサイトは見れるのに、この調査サイトだけが……」
　大塚先生の手はわずかに震えていた。彼は生徒たちの熱意を誰よりも知っている。このプロジェクトは彼らにとっての大きな挑戦であり、技術的なトラブルでその火を消したくはなかった。しかし、原因が特定できないことが、彼の焦りを煽っていた。

「……大塚先生、お疲れのところすみません。少し手伝わせてください」
　教室の後方から声をかけたのは、情報科の若手教員、日向先生だった。彼は手にタブレットを持ち、穏やかながらも確信に満ちた表情で歩み寄った。

「あ、日向先生……。いや、なんですかね。さっきまで動いていたのに、急にこのサイトだけ開けなくなったんです。他のGoogleのページやYouTubeは見れるんですよ。故障なのか、それともみんなの端末のせいなのか……」
　大塚先生は老眼鏡を押し上げながら、苦心の表情で答えた。

「いいえ、端末の故障ではありませんよ。おそらく、ネットワークの『層』のどこかで、特定の通信だけが遮断されている可能性が高いです」
　日向先生はそう言うと、自分のタブレットを開き、数秒でコマンドを入力し始めた。

「層……？ ネットワークの構造のことですか？」
「はい。インターネットという巨大な道の中に、いくつかのチェックポイントがあるんです。大塚先生が今、ケーブルを抜き差しして確認されているのは『物理的な道』の状態ですが、問題はもっと先の『案内標識』や『門番』にあるかもしれません」

日向先生は、教室の隅にあるWi-Fiルーターの近くへ移動した。
「まずは切り分けから始めましょう。大塚先生、この生徒さんのタブレットで、『Ping』というコマンドを打ってみてもらえますか？ 指定のサイトのIPアドレスに対してです」
「ピン……？ 私はそんなの知らないよ」
「大丈夫です、私が打ちますね。あ、今、こちらの端末から特定のURLに対してPingを打ちました。結果は『Request Timeout（タイムアウト）』です。しかし、Googleのドメインに対しては正常に応答が返ってきています」

日向先生の指が正確に動き、画面上の数値を解析していく。
「ここからが重要です。特定のサイトだけが開けない場合、原因は大きく分けて三つあります。一つ目は『DNSの名前解決』。つまり、URLをIPアドレスに変換する電話帳機能の不備。二つ目は『Webフィルタリング』。教育委員会や学校で設定しているプロキシサーバーによる遮断。そして三つ目は『CDN（コンテンツ配信ネットワーク）』のキャッシュの問題です」

日向先生は、自分の端末からプロキシサーバーの設定を確認し、同時にコマンドラインで「nslookup」を実行した。
「……あ、見つけました。原因はDNSの名前解決ではありませんね。名前は正しく変換されています。それなら、このサイトが特定の海外サーバーや、新しいサブドメインを使用していることによる『ホワイトリスト』の漏れです」

「ホワイトリスト……？」
　大塚先生が聞き返すと、日向先生は頷いた。
「はい。学校のネットワークにはセキュリティのためにプロキシサーバーを通ります。そこでは『許可されたサイト以外は見せない』という門番の役割を果たすんです。今回、この調査サイトが最近システムを更新して、新しいURL構造に変わったため、門番が『あ、これは知らないサイトだ！ 通さない！』と判断してしまったんですね」

日向先生はさらに続けた。
「大塚先生、今から私が教育委員会の管理システムにアクセスして、このサイトの新しいドメインをホワイトリストに追加します。それだけで解決するはずです。物理的なケーブルをいじる必要はありませんよ」

数分後、日向先生がタブレットを操作し終えた。
「終わりました。大塚先生、もう一度生徒さんに確認してもらえますか？」

大塚先生が教卓に戻り、生徒のタブレットを指さした。
「みんな、もう一度開いてみてごらん」
　生徒たちが一斉に画面をタップする。すると、数秒の待機の後、期待していた調査サイトのトップページが鮮やかに表示された。

「うわあ！ 開いた！！」
　教室が歓声に包まれた。生徒たちの顔にパッと笑顔が戻る。

「……すごいな」
　大塚先生は呆然としながら、日向先生を見た。
「私はまさか、あんなに苦労していた原因がたった一つの設定だったなんて思わなかったよ。君の知識、まるで魔法みたいだ」

「いえ、魔法ではありませんよ」
　日向先生は謙遜しながら笑った。
「大塚先生がいつも生徒さんのために動いてくださっているからこそ、技術でそれを支えたいと思っているんです。次は、このサイトだけでなく、他のよく使う教材もまとめてチェックして、自動的にホワイトリストに反映されるような管理表を一緒に作りましょう。そうすれば、次からはこんな大騒ぎにならなくて済みますよ」

大塚先生は深く頷き、初めて日向先生の肩を叩いた。
「ああ、頼むよ。君のような若手の知恵を借りて、この学校をもっと便利にしていきたい。教えてくれ、その『魔法』のやり方を」

窓の外には、依然として初夏の陽光が降り注いでいた。しかし、教室内の空気は先ほどとは全く違う、達成感と連帯感に満ちたものへと変わっていた。

【作中技術・ITネットワークのやさしい解説（Technical Commentary）】

今回の物語では、学校現場で頻繁に発生する「特定のサイトだけが開けない」というトラブルに対する、ネットワーク層に基づいた切り分け手法を解説しています。

1. OSI参照モデルに基づく障害切り分けとは
ネットワークの通信は、物理的な接続からアプリケーションの表示まで、いくつかの層（レイヤー）を経て行われます。トラブルが発生した際、「どこで止まっているか」を特定することが解決への近道です。
- 物理層（L1）: ケーブルは抜けていないか？ Wi-Fiの電波は届いているか？（大塚先生が行っていた確認）
- ネットワーク層（L3）: IPアドレス間の通信は通るか？（Pingコマンドで確認）
- アプリケーション層（L7）: ブラウザの設定、プロキシサーバー、DNSなどは正しく動いているか？

2. Pingと名前解決（DNS）の仕組み
- Ping: 特定のIPアドレスに対して「そこに誰かいますか？」という信号を送り、応答があるかを確認する最も基本的な診断です。
- DNSの名前解決: 私たちが入力する「google.com」などのURLを、コンピュータが理解できる「IPアドレス（例：142.250...）」に変換する仕組みです。もし「名前はわかるが、中身が見れない」のであれば、DNSではなくその先のフィルタリングが原因と特定できます。

3. 教育現場におけるプロキシ・Webフィルタリング
学校ネットワークではセキュリティ確保のため、すべての通信を「プロキシサーバー」という中継地点を通すことが一般的です。このサーバーには「ホワイトリスト（許可リスト）」があり、ここに登録されていないサイトへのアクセスを遮断します。
今回のように「以前は見れたのに見れなくなった」というケースでは、対象Webサイト側がシステムの更新等でドメイン（URLの一部）を変更したことが原因であることが非常に多いです。

4. 実践的な解決フロー
1. 範囲の特定: 全てのサイトが見れないのか、特定のサイトだけか？
2. Ping診断: 該当サイトのIPアドレスに対して応答があるか確認する。
3. DNS確認: URLからIPアドレスが正しく取得できているか確認する。
4. フィルタリング確認: 学校のプロキシ設定で、最新のドメインが許可されているかを確認し、必要に応じて更新する。
